# World startup and shutdown

`VerticalWorld` now preserves a reentrant shutdown request during primary-zone initialization, obelisk attachment, and primary-zone startup. It stops starting further zones, drains initialized owners when dispatch/leases permit, and returns `false` from `start`. Repeated shutdown requests during initialization remain deferred. This is native lifecycle safety, not a claim that the original uses these C++ callbacks.

Original context: `ps_game.exe` `CWorld::InitZones` 00414870 constructs the zones, `CWorld::GetZoneByMapID` 00413df0 selects them, and `CWorldThread::Update` 00407390 includes the minute quest-update gate at 0040771d–0040775a. The existing primary-zone authority owns the retained real zone, pool and obelisk objects; the unit's backends are fixtures.

`visit_primary_zones` exposes one leased traversal of actual permanent owners for a caller implementing a phase. The caller must serialize world operations. The authority recursive lock now remains held for the entire primary pass; shutdown and other authority dispatches defer until it exits. The original holds its world-thread zone-list lock across the update (ps_game.exe `CWorldThread::Update` 0040746d–00407475 and 00407c05), while this native lock also protects backend authority state and is released between separate calls; it is not a substitute for the complete original update lock. A shutdown requested in a visitor stops the traversal after that lease returns. A phased caller may leave the legacy frame provider empty; calling `frame()` in that configuration throws rather than reporting success. It does not visit dynamic instances, establish phase deadlines, or invoke gameplay itself. The original `CWorldThread::Update` 00407390 traverses its active zone list separately for each phase, so the existing whole-zone `frame` callback cannot reproduce cross-zone ordering. In order, the recovered calls are packet update (00407493, every update), user attack (004074c6, 100 ms), applied skills (0040750a, 1000 ms), effect tick (00407555, 3000 ms), effects (00407598, 5000 ms), mob then NPC attack (004075e8/004075f0, 500 ms), mob idle then traps (00407646/00407650, 1000 ms), NPC idle (004076a6, 3000 ms), items (004076f5, 10000 ms), and quests (0040773b, 60000 ms). Comparisons are unsigned and deadlines are set from the supplied tick after each pass. Further weather, rank, market, kill count, send and lifecycle phases follow. The production scheduler must retain the original complete active list including instance zones, preserve the remaining pass ordering and cursor behavior, and bind every pass to real owners before using this traversal as part of an assembly.
