# 09-persistence handoff

Implementation commits: e34441ab14c40de9b5869a5fa96f227379138230 and 16c934d944003517e32e5b167f1b6937c65a1b01 (final code). Scope is a selection-to-DB-cache adapter using the existing `Players`, `PointItemStore`, `CharacterReplica` and its component owners. The adapter preserves the selected snapshot for actor loading and returns the one replica to be retained by the DB user. It refuses relocated or overflow items until their load-time persistence semantics are integrated. It does not implement a server connection, world entry or a reconnect state machine.

Evidence: `ps_game.exe` `PacketCharacter` 0046bf20 forwards selection 0104 as 0407, and `PacketUserDBChar` 0046cf60, 0046d4c1..0046d717 handles successful selection. Existing DB owners recover `ps_dbAgent.exe` `DBCharacter::LoadCharacter` 00420610, `DBCharacter::SaveCharacter` 00423190..00424abe and `CUser::SaveCharacter` 00404f30. This adapter composes existing owners and does not claim independent original-execution validation of the composition.

Root integration contract: select through `vertical_persistence_select` with the actual account's roster max-grow, existing pools, SQL `Players` and `PointItemStore`. Retain the returned snapshot through actor load and retain the returned replica as the sole DB-user cache; serialize all `apply` calls and saving with the same recursive cache mutex. Route real DB-agent mutation packets to that replica and bind the existing `UserLifecycle` jobs and `CharacterSaveStore::save`/`save_exit` to it, with actual social, transport, queue, registry and recovery services. Pools, SQL connections and recovery file must outlive the owner. Call `character_loaded` only after complete successful loading and replication; on selection reset or disconnect wait for save job completion before releasing the replica, and create a fresh selection on subsequent login. Follow existing lifecycle ordering and timeout behavior. `Players::load` already updates JoinDate and consumes gift notifications before the adapter can reject a later load; failure cleanup must account for these side effects.

Limitations and next dependency: resolve original duplicate/overflow inventory repair and allocation failure behavior, integrate account-owned product and max-grow lifetime, and connect actual DB transport/selection/lifecycle and actor/world ownership. No successful placeholder services are supplied. No actual SQL round trip of this new adapter or original client playability is claimed.
