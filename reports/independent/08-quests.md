Evidence: ps_game.exe CUser::QuestStartRequest 0047f220, QuestStart 0047ea70, QuestUpdateKillMOB 00480140, QuestEndRequest 0047f2a0, QuestEnd 0047ec40, QuestEndSelect 0047ebe0; SSyncHeap<CNpc>::Alloc 0040acc0 retains LIFO reuse and object state. Pin/deferred release is a native callback-lifetime safety mechanism, not a claim that the original has an identical lease API. The composition test is not an original-executable trace comparison.

`NpcPool::pin` now owns the lease count. After canonical `ZoneNpcs::leave`, a direct `NpcPool::release` of a pinned NPC defers its reuse until the last lease ends; duplicate release and pinning a released or foreign NPC are rejected. Normal unpinned release remains LIFO. The pool reserves free/deferred storage when allocating NPCs, so a lease destructor does not allocate. Destroying a pool with outstanding pins terminates: the real pool must outlive all leases. All calls require the existing serialized executor. Quest start pins the actual zone lookup result using its actual pool and keeps it through callbacks; a foreign pool fails rather than silently borrowing an unprotected pointer. The former quest-specific retirement guard and its bypassable lifecycle authority have been removed.

Integration requirements: root must pass the actual pool that owns the NPCs of the supplied current zone to `VerticalQuests`, retain the pool, zone, NPC definitions and services through callbacks, and rebuild/rebind the adapter when the user changes zones. The pool and each NPC must not be independently destroyed while pinned. Direct normal pool release is protected; this does not make unsynchronized access or arbitrary direct mutation safe. Supply real clock, locks, client/database and log transports and a real `QuestRewardWorld` whose removal uses the same QuestRuntime. Route start/end/reward-selection requests and real mob/PC kill, item pickup and timer events. Shared production root wiring is coordinator-owned.
