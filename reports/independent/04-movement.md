The latter compares clipped 5-by-5 old/new view areas and constructs 0202/user-ID removal (0041f404–0041f49b); it also performs further visibility work, which needs complete reconstruction and original execution verification.

## Movement-check assignment

Implementation commit: `885b02d56b5aef717b2d6dd60692315f695a0d51`. `vertical_movement_update` operates on the existing `ZoneMovementCheck` and requires a clock callback. Original `ps_game.exe` `stUserMoveChk::Update` 0046a120 computes planar distance, accumulates it and the maximum supplied speed, updates previous position, and compares the unsigned clock to the deadline. At the deadline it accepts equality against `50 + elapsed_seconds * maximum_speed`, resets to the submitted position on acceptance or the retained back position on rejection, and samples the clock again in `stUserMoveChk::Reset` 0046a0b0. Reset advances its deadline with 32-bit wrap; elapsed time is unsigned wrapped subtraction. Before the deadline it retains the accumulated state and samples the clock once.

Original executable comparison: `tools/vertical_movement_oracle.py` executes both original functions and original CRT sqrt with 53-bit x87 precision. The 4,096 cases compare every state DWORD, result and clock-call count, including 50 and 55-unit exact boundaries and adjacent floats, accepted/rejected outcomes, variable speed, both deadline sides and wrapped clocks. The native focused test passed. Fixtures cover finite inputs; non-finite behavior and floating-point exception flags have not been verified.

Integration: `Actor::movement_check()` currently returns a const reference. The coordinator must expose serialized mutable access to that same `Actor` member, call this function at the original 0501 handler point with actual destination, speed and clock, and route its result through original correction and movement semantics. Do not create a second movement-check owner. This routine alone does not dispatch packets or provide visibility/world movement.

## Floating-point review

Review fix commit: `3ddd3a4e744283c9659267676dcbffaefe5e4392`. The movement check requires x86-64 SSE2, IEEE binary32/binary64, nearest rounding in both the C floating environment and MXCSR, and MXCSR FTZ/DAZ disabled. Unsupported environments and non-finite operands raise `std::logic_error` before the clock is sampled or state is modified. A finite input whose staged difference, distance or accumulated total overflows also raises after the first clock sample and before state mutation. The environment and operands are rechecked after that sample. The contract does not claim original non-finite propagation, FP exception flags, or support on other architectures.

The original-execution fixture still executes original CRT sqrt at x87 control word 027f; eight added cases cover subnormal operands and results. Tests additionally verify rounding-mode, MXCSR rounding, FTZ and DAZ rejection, non-finite rejection, overflow rejection, and state/clock behavior on those errors.

## Live movement dispatch stage

Implementation commit: `22551bc58ba8e2d7640150d3a0fa5146d614d6f1`. `vertical_movement_packet_check_after_gate` decodes the original 17-byte minimum 0501 request and invokes the recovered check against the actor's existing movement state.
