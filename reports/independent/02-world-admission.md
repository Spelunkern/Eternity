# 02-world admission handoff

Code baseline: `ce9151b2dcb36f9e5ef6b8c9feaf25fdbb8321c4`. This report is the only change in this assignment. No `vertical_admission` implementation is claimed: production selection and connection ownership are blocked by the shared interfaces below. Inventing another registry, treating instance maps as missing, or keeping an unprotected actor/zone pointer would change behavior or violate lifetime requirements.

## Evidence

- `WorldAdmission` already owns the real waiting and zone-wait lists. `ps_game.exe` `CWorld::WaitUser` 0040ce70 and `CWorld::UpdatePackets` 0040bf90 govern locations 1→2→3. Selection can call `ZoneRegistry::select` for create types 1–6, including party/rank/house instance owners; `ps_game.exe` `GetZoneByMapID` 00413df0 is the recovered selection boundary. `MobPrimaryZones` owns the sole actual `ZoneRegistry` privately and `lease(map)` selects permanent primaries only. Its `serialized()` gives no registry access or lifetime lease for an instance. `ZoneRegistry::select` returns a borrowed pointer, and standalone use would construct a competing registry.
- `WorldAdmissionUser::zone`, its zone-wait keys, `ZoneUsers`, and `WorldUsers` all retain raw pointers. The `WorldAdmission` contract requires users and zones to survive their membership and callbacks. `MobPrimaryZoneLease` protects only a primary zone, not an actor; `ZoneUsers::detach` and `WorldAdmission::untrack` must run while the actual actor and zone survive. No production `WorldApplication` here constructs or retains the selected `Actor`, `WorldAdmissionUser`, `ZoneEntryState`, `WorldUser`, and `ActorScene` together. `RosterApplication` handles roster operations only.
- `ps_game.exe` `CUser::ZoneEnterUserMove` 0044b8a0 checks assigned zone, rank/guild state and location 3; `CWorld::ZoneEnterUserMove` 0040d000 reselects and requires the user to be in that zone's wait queue. `CZone::EnterUser` 00415f80 sends the 0201 view packet after actual cell/user attachment, then shape/speed/cell/weather/obelisk/lifecycle services. Invalid coordinates close and requeue. The reconstructed `enter_zone_actor` implements this over the actual actor and zone, but its real cell, obelisk, scene and transport providers remain required.
- `WorldChannel` currently has send, enter-world, enter-selection and disconnect only. The socket executor decrypts every frame in a `FrameDecoder::feed` batch before the per-connection application worker finishes a prior request. Merely posting an asynchronous pause after location 2 can be too late for a coalesced later frame; the channel/protocol transition and buffered raw frames need ordered handling.

## Required coordinator integration

1. Extend the **same** `MobPrimaryZones`/`ZoneRegistry` authority with a serialized `select(map, ZoneUserAccess)` that calls its existing registry and returns a retained, generation-checked lease for the actual selected `RuntimeZone`, including dynamic instances. Acquire selection and lease atomically; visit under the same executor; prevent release/recycling while any queue, actor membership, dispatch, or callback holds the lease. A missing/invalid selection must retain original failure behavior. Drain/shutdown must wait for all instance as well as primary leases. Expose the same registry's real local time/rank path; no second registry.
2. Provide a connection/user lifetime owner retaining the real `WorldAdmissionUser`, `Actor`, `ZoneEntryState`, `WorldUser`, `ActorScene`, channel and required real backends until all admission callbacks, world indexes and zone membership have finished. Serialize its mutations through the same authority; defer destruction from reentrant callbacks. Hold the exact selected zone lease from location 3 through failed-entry requeue and successful attached membership. On disconnect, stop input, untrack admission, leave the actual world index and detach the actor from the actual `ZoneUsers` in the recovered lifecycle order before releasing the lease and actor. The complete leave/disconnect ordering and providers need independent evidence; do not substitute a bare detach for the full original lifecycle.
3. Bind an actual `WorldAdmissionServices` to the existing one `WorldAdmission` and `WorldUsers` owner. `select_zone` must return the leased actual `RuntimeZone`; `enter_zone` calls `enter_zone_actor` on that exact zone and actor with live scene/grid-view, cell info, obelisk, NProtect, diagnostic and close providers. Implement live rank clock, guild lock/counter, world registration, packet dispatch and network transport; do not use successful placeholders. Retain the queue's exact zone when `world_enter` reselects; mismatched queue ownership cannot be silently accepted.
4. Coordinator ingress branch `6d68908` proposes `pause_input` with asynchronous acknowledgment on the socket executor. Its API and tests are not yet validated here. Root integration must await successful acknowledgment without blocking either executor before transferring to world admission; resume only once `update_packets` has installed location 3 and retained the selected zone lease. Order the real `WorldChannel::enter_world` transition before resuming buffered input. Confirm that the ingress implementation also holds subsequent encrypted frames before decoding, including frames already returned in the same decoder batch; an acknowledgment alone does not establish that property. On pause failure, failed selection, or disconnect, resolve the pending operation without processing stale input, and retain the connection/user until callbacks complete.

A successful production test must cover primary and instance selection, location 2 pause, location 3, real 0201 delivery/membership, invalid-position failure and requeue, guild/rank lock behavior, and disconnect at each pending stage with actual retained owners. Current focused component tests are not that production test.
